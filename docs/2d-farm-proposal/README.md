# 2D 农场表现方案（QQ 农场那种）

> 目标：农场从「emoji 方块网格」变成有地块、有作物生长阶段、有动物、有点击反馈的
> 2D 农场。**结论先说：不要上游戏引擎。** 用「DOM 布局 + 内联 SVG 精灵 + CSS 动画」。
>
> 可交互原型：同目录 `demo.html`（单文件、零依赖、零外部请求，直接双击打开）。

---

## 一、为什么不上 Pixi —— 四条理由，按重要性排

### 1. ★★ 会把项目最贵的验收资产全废掉

现有 **4 个脚本、约 16 处**靠 DOM 定位农场：

```
document.querySelector('div.grid.grid-cols-3 > button')     // 定位 12 块地
top?.closest('div.grid.grid-cols-3')                        // 遮挡探针：点到底落谁身上
```

`capture.mjs` / `e2e-bag-sell.mjs` / `e2e-gameplay.mjs` / `e2e-regressions.mjs` 全在用。
换成 canvas 之后：

- 地块**不再是可以点的元素**，`tiles[i].click()` 直接失效；
- **遮挡探针没法做了** —— canvas 里「谁盖住谁」是渲染顺序，不是 DOM 树；
  要测得自己维护一份命中区镜像，而那份镜像**和真实渲染是两份事实**（本项目最怕的走散）；
- 截图走查还能拍，但**拍不出「可点击性」**。

原型 `demo.html` 特意保留了 `div.grid.grid-cols-3 > button` 这个结构，
脚本一行都不用改 —— 这是本方案最大的好处。

### 2. 体积：一个最小的 Pixi，几乎等于整个 App 现在的大小

本机实测（esbuild `--bundle --minify`，gzip 后）：

| 打包内容 | raw | gzip |
| --- | --- | --- |
| **现有整个 App**（4 个 tab + 农场 + 市场 + 积分 + 全部业务逻辑） | 594,769 | **176,456** |
| Pixi 最小用法（`Application` + `Sprite` + `Assets`） | 589,003 | **172,947** |
| Pixi 农场级用法（再加 `Text` / `Graphics` / `滤镜`） | 622,280 | **183,632** |

加进来 JS 直接翻倍（176 KB → 约 350 KB gzip）。
它换来的能力是**上千精灵、着色器、粒子系统** —— 而我们只有 **12 块地 + 8 只动物**。

> 复现：`npm i pixi.js esbuild`，bundle 一个最小入口，`gzip -c out.js | wc -c`。

### 3. 无障碍与文字

地块上的「空地 / 枯萎了」、飘字「+16」、动物名字，在 DOM 里是**真文字**：
能被读屏念、能跟系统字号缩放、能被 Ctrl+F 搜到。
canvas 里这些都要自己重画一遍，且**家长调大系统字号时不会跟着变**。

### 4. 低端机耗电

CSS 动画只动 `transform` / `opacity` 时走**合成层**，静止时**完全不占 CPU**。
WebGL 是**常驻渲染循环**（`ticker` 一直跑）。孩子用的是旧安卓机，
农场页面一开就 60fps 空转，是实打实的耗电和发热。

## 二、推荐架构：三层，各管各的

```
┌─ 布局层 ── CSS Grid（现有 div.grid.grid-cols-3，12 块地）
│
├─ 精灵层 ── 每块地内嵌一个 <svg><use href="#s-carrot-2"/></svg>
│            生长阶段 = 换一个 href（不是换图、不是重绘）
│            所有图案在一个隐藏的 <svg class="sprite"> 里定义一次
│
└─ 效果层 ── CSS @keyframes（项目里已经有 13 个关键帧：
              anim-sway / anim-pop / anim-coin-rise / anim-sparkle …）
             + 少量 SVG 滤镜（成熟时的 drop-shadow 发光）
```

**为什么精灵用内联 SVG 而不是 PNG：**

- 矢量，任意 DPR 都清晰（低端机 1x、iPad 2x/3x 都不用出多套图）；
- 一个阶段就是一个 `<symbol>`，**换阶段只改 `href`**，没有加载/解码开销；
- 体积小：原型里 15 个图案（3 作物 × 3 阶段 + 地皮 + 枯萎 + 3 动物）全加起来
  还不到 10 KB，而同等数量的 PNG 至少几百 KB；
- **和项目现有做法一致** —— `site/` 的图案早就全用内联 SVG 了
  （21 个 `<symbol>`），不用 emoji 的理由也一样：**emoji 的粗细由系统字体决定，永远调不了**。

**项目里已经有一条成功先例：** `src/features/splash/SplashPage.tsx` ——
**344 行手写 SVG 场景**（19 个 path / 9 个 ellipse / 3 个渐变 / 10 个 group）
配 CSS 动画（日出、云飘、叶子摇摆、星光闪烁），零依赖、零外部请求。
农场照这条路走，**风格还能和启动页统一**。

## 三、真正的成本是美术，不是引擎

| 素材 | 数量 |
| --- | --- |
| 作物 | 15 种 × 4 个阶段（种子 / 幼苗 / 生长 / 成熟）= **60** |
| 枯萎态 | 1（所有作物可共用） |
| 动物 | 8 种（走动各 2~4 帧可选） |
| 地皮 | 生土 / 已开垦 / 已浇水 = 3 |
| 特效 | 浇水水滴、收获闪光、飘字 —— 用 CSS 就够，不需要素材 |

**约 90～100 个素材。** 这部分**无论用 DOM 还是 Pixi 都要做**，
所以先把钱和时间花在素材上，表现层选最省事、最可测、最不容易翻车的。

### 素材三个来源

| 来源 | 优点 | 坑 |
| --- | --- | --- |
| **CC0 素材包**（Kenney.nl、OpenGameArt） | 免费商用、风格统一、就是给游戏设计的 | 风格未必贴合现在的暖色绘本风；需要挑一套并统一调色 |
| **AI 生图** | 快、风格可控 | **跨 90 张的一致性最难**（同一作物 4 个阶段要像一家人）；透明背景要额外处理；尺寸/描边/光源方向要统一规范 |
| **自绘 SVG** | 完全贴合现有风格、体积极小、可程序化调色 | 耗时；适合先做 3~5 种跑通闭环，再决定要不要外包 |

**建议**：先用自绘 SVG 做 **3 种作物 + 2 种动物**跑通完整闭环（就是 `demo.html` 的量），
确认观感和节奏之后再决定美术从哪来。**别一上来就买 90 张图。**

## 四、分阶段路线（每阶段都能单独上线）

| 阶段 | 做什么 | 风险 | 验收 |
| --- | --- | --- | --- |
| **0** | 地块底图 + 3 种作物的生长阶段 SVG，替换现在的 emoji | 极低，DOM 结构不动 | 现有 6 个 e2e 套件照常全绿；`div.grid.grid-cols-3 > button` 仍在 |
| **1** | 浇水 / 收获 / 枯萎的动画 + 飘字（复用已有 `anim-coin-rise`） | 低 | 截图走查 + `prefers-reduced-motion` 降级 |
| **2** | 动物在围栏里走动（CSS `translate` + 路径动画，就是原型的做法） | 低 | 同上 |
| **3** | 昼夜 / 天气 / 粒子 | 中 —— **到这里才评估 canvas** | 见下面「什么时候才该上 Pixi」 |

**阶段 0 是唯一必须做的事**，而且它不改任何 DOM 结构、不加任何依赖。

## 五、什么时候才该上 Pixi（触发条件）

满足**任意一条**再考虑，不要凭「感觉更专业」上：

1. 同屏精灵数 **> 500**（现在最多 ~100）；
2. 需要**真粒子系统**（成千上万的雨/雪/落叶，CSS 撑不住）；
3. 需要**着色器**（水面折射、动态光照、热浪扭曲）；
4. 需要**骨骼动画**（Spine / DragonBones 那种角色动作）。

**而且即使满足，也先试「裸 Canvas 2D」** —— 它是浏览器内置的，**0 KB**。
Pixi 值 173 KB 的理由是 WebGL 批量绘制与着色器；只是要画几个会动的图，
Canvas 2D 就够了。**引擎不是拿到 canvas 的唯一途径。**

### 如果真要用 canvas：混合渲染，别全换

保持 **DOM 精灵 = 交互层 + 可测层**，canvas 只做**背景/效果层**：

```html
<canvas class="fx" aria-hidden="true"></canvas>   <!-- position:absolute; pointer-events:none -->
<div class="grid grid-cols-3"> …12 个 button… </div>
```

- `pointer-events:none` 让 canvas 不挡点击，DOM 命中测试照旧；
- e2e 定位、遮挡探针、无障碍**一样都不丢**；
- canvas 只负责「好看但不需要被点到」的部分。

## 六、性能与降级清单

- `prefers-reduced-motion: reduce` → 关掉所有循环动画（项目已有这个习惯，`farm.css` 里就有）；
- 动画**只动 `transform` / `opacity`**，别动 `width` / `top` / `margin`（会触发布局重排）；
- 用 `will-change` 要克制，用多了反而吃显存；
- 低端机上「12 块地同时摇摆」这种要限流（原型的 `sway` 是 3.2s，够慢）；
- 位图素材才需要图集（atlas）；**SVG 不需要**。

---

## 七、素材规范（不管最后谁来画）

| 项 | 建议 |
| --- | --- |
| 画布 | SVG `viewBox="0 0 80 80"`；位图 128×128（1x）/ 256（2x） |
| 光源 | 统一左上打光（现有 UI 的阴影都是这个方向） |
| 描边 | 统一粗细（原型用 2.4~3.4，随形体大小微调） |
| 配色 | 从 `theme.css` 的变量取：草地绿 `#16a34a`、太阳黄 `#f59e0b`、土棕 `#a37f5a` |
| 透明 | SVG 天然透明；位图用 PNG-32 |
| 命名 | `s-<crop>-<stage>`（如 `s-carrot-2`），直接对应 `<use href>` |

## 八、原型里已经验证过的

`demo.html` 跑起来之后：

- ✅ 12 块地仍是 `div.grid.grid-cols-3 > button`（脚本自检：地块数 12 / 都是 button / 每块都有 svg / 遮挡探针可用）；
- ✅ 三种作物各 3 个生长阶段，切换只是换 `href`；
- ✅ 空地 / 生长中 / 成熟 / 枯萎 四种状态，成熟有金圈 + 闪光 + 发光；
- ✅ 浇水（水滴）、收获（`+16` 飘字）、点按回弹；
- ✅ 动物在围栏里走动（狗 / 鸡 / 北极熊，反向错开）；
- ✅ 全程零控制台报错、零外部请求；
- ✅ `prefers-reduced-motion` 降级。

---

## 九、一句话总结

**农场「像 QQ 农场」靠的是素材和动画节奏，不是引擎。**
先把 SVG 精灵和 CSS 动画做到位（阶段 0~2），
等真的需要「上千粒子 / 着色器 / 骨骼动画」时再谈 canvas —— 而且先试裸 Canvas 2D。
