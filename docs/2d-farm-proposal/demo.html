2D 农场 · 方案原型

用 DOM + 内联 SVG 精灵 做出「QQ 农场」那种观感：地块、生长阶段、浇水、收获、动物走动。
零新依赖、零外部请求。下面这 12 块地和现有 App 是同一个 DOM 结构 （div.grid.grid-cols-3 > button），所以 4 个 e2e 脚本和遮挡探针都不用改。

种什么：

这个原型证明的三件事

① 不用引擎也能有「图片感」——上面每个作物都是手写内联 SVG，三个生长阶段各一个 <symbol>，切换只是换一个 <use href>。
② DOM 契约没变——地块还是 button，还是 div.grid.grid-cols-3， 点击/遮挡/截图全都能照旧测。
③ 动画都是 CSS——摇摆、浇水水滴、收获飘字、动物走动，全是 @keyframes，并且带 prefers-reduced-motion 降级。

为什么不上 Pixi —— 实测的体积账

打包内容rawgzip
现有整个 App（4 个 tab + 农场 + 市场 + 积分 + 全部逻辑） 594,769176,456
Pixi 最小用法（Application + Sprite + Assets） 589,003172,947
Pixi 农场级用法（+ Text / Graphics / 滤镜） 622,280183,632

一个最小的 Pixi 包，几乎等于整个 App 现在的大小。 加进来 JS 会翻倍（176 KB → 约 350 KB gzip），而它换来的能力 （上千精灵、着色器、粒子）在「12 块地 + 8 只动物」这个量级上一点都用不到。

真正的成本是美术，不是引擎

15 种作物 × 4 个阶段 = 60 张图，8 种动物，12 块地皮，再加特效 —— 约 90～100 个素材。 这部分无论用 DOM 还是 Pixi 都要做。所以先把钱和时间花在素材上， 表现层用最省事、最可测、最不容易翻车的方案。
